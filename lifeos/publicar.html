O token é guardado no seu Supabase, não no navegador nem no repositório. Depois de salvo ele nunca é exibido de volta — só as pontas.
  1. Abra github.com/settings/personal-access-tokens/new — ou, no GitHub: sua foto → Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token.
  2. Dê um nome que você reconheça depois (ex.: lifeos-publicar) e escolha a validade. Token sem validade é conveniente e arriscado: se vazar, vaza para sempre. 90 dias é um meio-termo razoável.
  3. Em Repository access, escolha Only select repositories e marque apenas o repositório do seu archive. Nunca dê acesso a todos.
  4. Em Permissions → Repository permissions, encontre Contents e mude para Read and write. É a única permissão necessária — é ela que deixa o publish criar o commit. Deixe todo o resto como está.
  5. Clique em Generate token e copie o valor. O GitHub só mostra uma vez — se perder, não dá pra recuperar, só gerar outro.
  6. Cole no campo acima e salve. O status no topo da aba Publicar página deve passar a verde.
Token clássico (ghp_…) também funciona: precisa do escopo repo. O fine-grained é preferível por dar acesso a um repositório só.
Entenda o que este token permite. Para publicar, a página precisa dele no navegador — ou seja, quem souber a senha mestre e abrir esta tela consegue escrever no seu repositório. Por isso: use um token com acesso a um repositório, só a permissão Contents, e com validade. Se suspeitar de vazamento, revogue no GitHub — revogar lá invalida na hora, apagar aqui só remove o registro.
